# 暴走台球 — 后续设计备忘

> 以下含早期方案。单人、回合联机和使坏卡现已实现；现行规则、计分与协议以 [NETWORK_SYNC.md](NETWORK_SYNC.md) 为准。

游戏名是**暴走台球**。单人已经是每打进或砸碎 3 颗球抽一张卡（加力上限、白球胀大、球增重、磁铁球），清台直接开下一波。联机仍是每 3 个回合双方各抽一张。下面只记还没做的方向。

This file is the living list of follow-ups. v1 shipped single-player only.

## 负面效果（过关诅咒 / 混进增强池）

正面增强已经能叠。下一版把**诅咒**混进过关三选一，或者做成「再抽一张必须带一个诅咒」。诅咒要改的是同一套物理量，不要另起一套模拟。

### 1. 增加球台摩擦力

- **玩家观感：** 球更早停，走位变短，砸击窗口变窄。高蓄力仍然能撞网，但落地之后立刻「粘」在绒面上。
- **改哪里：** `PHYS.feltMu`（库仑段）和 `PHYS.feltVisc`（粘滞段，已经除以质量）。诅咒每层：`feltMu *= 1.45`，`feltVisc *= 1.25`。
- **和现有增强的关系：** 「球增重」靠粘滞/质量让球滑得更远；高摩擦会把这条优势削掉，逼玩家改抽加力或磁铁。
- **表现：** 绒面色更深、球后拖出短粉尘；HUD 记 `GRIP n`。
- **别做成：** 把 restitution 一并砍掉。那是垫子弹性，不是摩擦。

### 2. 球台崎岖不平

- **玩家观感：** 直线不再是直线。球在绒面上被微微抛起、改道，像石板裂了又用绒布盖上。
- **改哪里：** 现在毡面是平面 `y = feltY`。改成高度函数 `feltY + amp * n(x, z)`，法线由高度场导数给出。碰撞用该点的局部平面，不要用 mesh 的每个三角形当刚体。
- **amp 建议：** 第一层 ±0.012（约球半径的 1/10），第二层 ±0.028。再大就会像蹦床，不像台球。
- **和铁网的关系：** 崎岖主要改台面上的滚动；飞起来之后仍由铁网/天花板接管。不要让高度场在袋口附近鼓包，否则球会「跳过袋口」。袋口半径内 amp 强制为 0。
- **表现：** 毡面用同一张高度场做 vertex displacement，灯光才能和碰撞一致（渲染和碰撞必须来自同一高度场）。
- **别做成：** 随机每帧抖高度。必须是这局固定的噪声种子，否则无法学习。

### 3. 球的重量减轻

- **玩家观感：** 一撞就飞、一碰就飘、铁网上弹得更碎。砸击伤害下降（动能小），但飞笼变日常。
- **改哪里：** 与「球增重」同一条 `massMul`，往下叠：`massMul *= 0.62` 每层。粘滞项 `feltVisc / mass` 会自动让轻球更容易被拖停——如果希望轻球「发飘还滑」，诅咒层同时把 `feltVisc` 略降。
- **和加力上限：** 轻球 + 加力 = 球会经常砸天花板。这是想要的暴力，但要保留袋口仍可进（向上速度过大时袋口吸力可以略增，避免永远跳过）。
- **表现：** 球的金属度略升、落台声音更脆；HUD 记 `LIGHT n`。
- **别做成：** 缩小半径。减重不是变小；变小是白球胀大的反面，以后如果要做再单独开一条。

### 诅咒怎么进局

推荐两种，先做一种即可：

1. **混池：** 过关仍抽 3 张，但波次 ≥ 3 时其中 1 张有概率是诅咒。可以跳过（少一张增强）。
2. **强行带诅咒：** 每 3 波弹出「祝福 + 诅咒」各一，必须都接。更像肉鸽。

第一版的四张增强继续可叠加。诅咒与同名增强对冲（重 vs 轻、滑 vs 粘），不要互相删除层数，让玩家在 HUD 上同时看到 `HEAVY 2` 和 `LIGHT 1`。

## 联机对战

第一版没有服务器。联机不要把单人物理循环拆掉，在上面加房间层。

### 模式（按实现成本）

1. **热座 / 本地轮流（先做这个）**  
   同一张桌子、同一铁笼。玩家 A 打完一杆，球停稳后换 B。各带自己的增强（白球半径、加力、磁铁只作用于自己的白球；「球增重」若是全局则两人共享，建议改成「我的白球增重」以免互相踩）。
   胜负：先清掉属于对方的彩球，或把对方白球砸进袋 N 次。

2. **同步对打（一张桌两颗白球）**  
   两人同时蓄力开球。铁网让飞球对双方都危险。需要锁定步物理（固定 dt 已经有了）和输入确认。
   建议锁步：客户端预测自己的白球，权威服务器每杆结算。不要试图 60Hz 同步每颗球的位置，台球对位置误差极敏感。

3. **异步房间 / 挑战种子**  
   把 `runSeed + 波次 + 增强序列` 做成可分享种子。对方打同一波布局比分数。这不需要实时同步，适合先于真联机上线。

### 协议草案（真联机时）

- 房间：`create / join / ready`
- 一杆：`{ playerId, aimDir, power, loft, tShot }`
- 权威：服务器用与客户端同一份 `Sim.step` 重放，回 `ballHash`（各球 pos/vel 的短哈希）。哈希对不上就整杆重放，不要每帧纠偏。
- 增强：每波只在过关 RPC 上选择，选完广播 `modsByPlayer`。
- 反作弊：只信服务器的进袋/砸碎；客户端特效可以预测。

### 不要先做的

- 物理在两边各跑再插值（台球会穿袋、双进）。
- 帧同步但没用固定 dt（现在 `1/60` + substeps，联机时把渲染插值留在客户端，模拟不要跟刷新率走）。
- 语音、大厅装潢。先能打完一局。
