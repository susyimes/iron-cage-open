# 娱乐八球：规则与联机同步

当前模式是带增强与使坏卡的简化八球。规则参考 [WPA 2026 八球规则](https://www.wpapool.com/wp-content/uploads/2026/01/2026.01.02-WPA-Rules.pdf)，娱乐化简化为不报袋、联机犯规全台自由球、单人犯规自动复位白球；支持调抬杆角度跳球，不支持击碎彩球或指定袋口。

## 规则

- 15 颗彩球，1–7 为全色，9–15 为花色，8 为决胜球。开球不分组；之后首颗合法入袋的非黑球确定双方花色。同杆进两种花色时按进袋事件顺序确定。
- 开球须有彩球进袋，或至少四颗不同彩球碰库。开球进黑 8 时把黑 8 放回置球点附近空位，其余球不动；合法开球进球可以继续，开球犯规则换手并给自由球。
- 正常杆必须先碰本组球；本组全部清完后才可先碰黑 8。开放球台不得先碰黑 8。
- 合法进本组球继续出杆；未进本组球则换手。误进对手球留在袋中，并计入对手组的完成进度。
- 白球落袋、未碰彩球、先碰错球、碰球后无进球且无球碰库，均犯规。犯规时不加分；联机时对手全台自由球，必须先在合法空位摆白球才能击球。
- 开杆前本组已清完，且合法打进黑 8，才获胜。提前进黑 8、最后一颗本组球与黑 8 同杆进袋、进黑 8 同时犯规均判负。
- 分数是辅助反馈，不决定胜负。合法本组进球每颗 100 分，合法黑 8 额外 100 分；开球的非黑球每颗 100 分。
- 单人是八球练习：使用相同的开球、分组、首次碰球及黑 8 判罚；普通犯规后白球自动回到开球位置，被占时选附近空位，其余彩球保留落点。单人不进入自由球摆放，立即恢复瞄准；合法黑 8 通关、提前黑 8 结束。每合法进 3 球抽卡。
- 联机累计每 6 杆双方各抽一次，连杆也计入杆数，避免只按双方出杆次数相等触发而漏掉选卡。每种卡最多 4 层。

## 卡牌归属与球台不变量

增强写入选择者的 `mods`，使坏只写入对手的 `curses`。物理配置取当前出杆者 `turn`；HUD 分别标明“你的增益”“你受使坏”“对手受使坏”。观战时看到的是对手这一杆的效果，不代表施加给自己。

八球卡池保留加力、增重、磁力、打滑、发粘和轻白球。尺寸类卡（大白球、大彩球、小白球）暂不进入八球卡池；八球始终使用固定物理半径，禁止换手重新分离彩球。即使收到旧尺寸元数据，也不会改变八球的尺寸或球位。卡片图标和画面风格不变。

摩擦、重量与磁力只在所属玩家出杆时使用。换手恢复下一位的配置，不移动球心。磁力在出杆后两秒内衰减到零，不持续唤醒整桌球。静止球接触与微小穿透校正不再重置休眠时间，普通轻杆无需等到硬超时。

只允许有规则含义的重新摆放：白球落袋或单人犯规后的自动复位、联机获得自由球后的主动摆放、开球进黑 8 的置球。这些操作都不移动其他彩球，且 HUD 会明确提示。

## 协议 v4 与时序

共享的 `shot.ts` 负责 1/60 秒物理步、输入规范化、抬杆角度对应的垂直冲量、快照与进袋去重；`rules.ts` 收集有序首次碰球、碰库事件和开杆前剩余球，单机与服务器使用同一判罚函数。单人结算再将普通犯规转换为白球自动复位，清除自由球状态。每杆默认平击，只有玩家抬杆才改变出球仰角。

1. 松手后客户端立即预测出杆，同时发送 `shot(requestId, revision, input)`。
2. 服务器校验回合、版本、请求编号、参数和自由球是否已摆放，通过后立即广播 `shot-start`。出杆方收到确认不重放；观战方从开杆快照开始。
3. 服务器按固定步推进，各客户端使用相同顺序的球数组、启用球袋的八球配置和当前玩家效果模拟。服务器每次时钟最多推进 8 步，客户端每帧最多 16 步。低帧率不再丢弃 50 ms 以上的正常帧时长。
4. 停球后服务器判罚、确定下一位、授予自由球或结束对局，广播 `shot-end(shotId, steps, result, state)`。客户端完成对应步数后应用权威状态与结算。
5. 自由球使用 `place(x, z, revision)`；服务器校验身份、阶段、版本、台面范围、袋口及球间距。成功后更新版本并广播，未摆球不能出杆，迟到或重复摆球不能移动球台。
6. 联机结算后，双方发送 `rematch(game)` 表示准备好。先点的一方留在结算页等待，第二人确认后服务器在原房间重摆 16 球，重置花色、分数及卡牌，轮换开球者。连接和座位保留；`game`、`revision`、出杆请求及 shot ID 防止旧局消息影响新局。对手离开或断线后禁用重开，不回退单人模式。

`state.rules` 包含花色、是否开球、自由球归属、胜者及最近判罚。`revision` 标识球台版本；同次抽卡两人共享版本，先选不使另一人过期。`requestId` 与 `shotId` 防止重复执行和迟到消息覆盖新球局。

球快照包含位置、速度、半径、质量、休眠、入袋进度、袋口与计分标记。恢复时严格保留服务器的球数组顺序，避免客户端复用主界面球模型后改变碰撞求解顺序。每次进入联机、恢复状态都启用球袋，修复主界面演示关闭球袋的配置泄漏。

每杆正常仅发开杆与结算快照，不下载完整轨迹。后台恢复主动 `sync`，移动状态从快照步数继续。断线后锁定输入，中途离开判弃权，不支持重新占座。不同浏览器若出现数值差异仍以服务器为准；后台恢复属于显式权威同步，不能承诺无网络延迟。

## 房间生命周期

输入 4 位字母或数字：有房加入，无房创建；留空随机创建。成功入房、出杆、摆球、选卡或首次确认再来一局续期五分钟。心跳、同步、无效或重复操作、物理推进均不续期。超时关闭双方连接（`4001`）、释放房间码；旧连接迟到事件不能删除新房间。最后一人离开即释放。

## 验证

- `npm run test:online`：输入及重复命令、确定性模拟、中途恢复、八球判罚矩阵、真实进袋连杆、使坏跨回合隔离、自由球权限/位置/版本、休眠、房间生命周期和客户端迟到消息。
- `npm run test:visual`：576 个镜头范围组合及特效预算。
- `node scripts/browser-selftest.mjs`：实际 Chromium 桌面与手机视口，双向各加 150 ms 消息延迟；出杆即时预测、八杆联机及抽卡、约 10–12 fps 手机备用循环、中途同步、每次换手的彩球校正距离、自由球鼠标/触屏摆放、单人合法黑 8、弃权与手机禁止复制。

浏览器检查需先 `npm run build` 并运行服务器。`QA_URL` 指定测试地址，`PLAYWRIGHT_MODULE` 指定 Playwright 模块 URL，`CHROMIUM_PATH` 指定 Chromium 路径，`QA_OUTPUT_DIR` 指定截图与报告目录。浏览器在后台运行。
